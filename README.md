# شهادات الفصل الدراسي الأول — 2026/2027
مدرسة أبو القاسم الزهراوي للتعليم الأساسي (٥–٩).

## الحالة الحالية
واجهة جاهزة، وقائمة الطلاب فارغة. لا توجد شهادات أو بيانات من العام السابق.

## تجهيز الطلاب
اعتمد قائمة هذا العام. الملف students.json عبارة عن مصفوفة سجلات:
```json
[
  {
    "civil_id": "12345678",
    "student_name": "اسم الطالب",
    "grade": "الخامس",
    "class": "5-1",
    "pdf": "pdfs/5-1/12345678.pdf"
  }
]
```
المثال توضيحي فقط. احفظ الأرقام المدنية نصوصًا للحفاظ على الأصفار.
قبل رفع شهادة، اترك pdf فارغًا ليظهر أنها قيد التجهيز.
لا تكرر الرقم المدني، وطابق الاسم والصف والشعبة مع الشهادة.

## رفع ملفات PDF
لكل طالب ملف مستقل باسم رقمه المدني، داخل مجلد شعبته مثل pdfs/5-1/.
الموقع يعرض الملفات المرفوعة؛ لا يصنع الشهادات أو يحتسب الدرجات.

## النشر
سير العمل .github/workflows/pages.yml يتحقق من البيانات والملفات ثم ينشر عبر GitHub Pages.
إذا لم يتفعل Pages تلقائيًا: Settings → Pages → Source → GitHub Actions، ثم Actions → Deploy certificates → Run workflow.
الرابط المتوقع: https://sc1561.github.io/Certificates-2026-2027-Term1/

## الخصوصية
المستودع عام؛ بيانات الطلاب وملفات PDF متاحة مباشرة. البحث بالرقم المدني ليس تحققًا من الهوية. يلزم نظام استضافة مع تحقق من الهوية إذا كانت الشهادات تتطلب وصولًا خاصًا.

## نسخة الفصل الثاني
استخدم مستودعًا مستقلًا، وحدّث العنوان والفصل والرابط، وأرفق شهادات الفصل الثاني فقط.

## برومبت تجهيز شهادات شعبة — التقسيم وإنشاء JSON

هذا نص تعليمات للنسخ مع المرفقات، وليس برنامجًا يعمل بمجرد إضافته إلى README.
تحتاج الأداة المستخدمة إلى القدرة على قراءة PDF وتشغيل أدوات تقسيمه وإرفاق الملفات الناتجة. جودة الاستخراج تعتمد على الملف، وتستلزم مراجعة الحالات الملتبسة.

### ما الذي أرفقه؟
- ملف PDF الأصلي لشعبة واحدة أولًا.
- قيمة الشعبة صراحةً، مثل `5-1`، واسم الصف، مثل `الخامس`.
- ملف `students.json` الحالي إن وُجد؛ يمكن أن يكون فارغًا `[]`.
- يُفضّل قائمة الطلاب الرسمية لهذا العام في Excel أو CSV للتحقق من الاسم والرقم المدني والصف والشعبة.
- عند متابعة شعبة جديدة، أرفق JSON المحدّث من آخر جولة، لا نسخة قديمة.

### البرومبت الجاهز للنسخ

````text
أنت متخصص في معالجة شهادات الطلاب العربية، وتقسيم PDF، والتحقق من مطابقة الهوية، وإنتاج ملفات قابلة للرفع إلى مشروع GitHub Pages.

نفّذ العمل باستخدام أدوات معالجة الملفات المتاحة لديك. لا تكتفِ بوصف الطريقة، ولا تدّعِ إنشاء أو فحص ملف لم تنشئه أو تفحصه فعلًا. إذا كانت الأدوات المطلوبة غير متاحة، اذكر ما تعذر إنجازه بوضوح.

بيانات هذه الجولة:
- المدرسة: مدرسة أبو القاسم الزهراوي للتعليم الأساسي (٥–٩).
- العام الدراسي: 2026/2027.
- الفصل: الفصل الدراسي الأول.
- الصف: [اكتب اسم الصف هنا].
- الشعبة: [اكتب رمز الشعبة هنا، مثل 5-1].
- المرفقات: PDF لشعبة واحدة، وstudents.json إن وجد، وقائمة الطلاب الرسمية إن توفرت.
إذا كانت قيمة الصف أو الشعبة غير معروفة، افحص المرفقات لتحديدها. إذا بقيت ملتبسة، اطلب هذه المعلومة قبل إنشاء مسارات النشر.

الهدف:
تقسيم شهادات الشعبة إلى ملفات PDF أصلية مستقلة، وربط كل شهادة بصاحبها الصحيح، وإنشاء أو تحديث students.json دون تخمين أو خلط بين الطلاب.

1. فحص المرفقات قبل التقسيم
- افحص العدد الفعلي لصفحات PDF ونوع المحتوى: نص، صور، أو مزيج منهما.
- تحقق من العام والفصل والمدرسة والشعبة حيث تظهر في الشهادات، وسجل التعارضات.
- لا تفترض أن عدد الصفحات يساوي عدد الطلاب؛ قد توجد أغلفة أو صفحات فارغة أو شهادة من أكثر من صفحة.
- استخدم صفحة واحدة لكل شهادة فقط عندما يؤكد المحتوى ذلك. إذا وجدت شهادة متعددة الصفحات، اجمع صفحات الطالب نفسه بعد التحقق. إذا لم تتضح الحدود، أوقف هذه الحالة للمراجعة.
- لا تعتمد على ترتيب الطلاب في القائمة لتحديد صاحب الصفحة.
- احتفظ بالملف الأصلي دون تعديل.

2. استخراج الهوية والتحقق
- استخرج الرقم المدني من الحقل المسمّى «الرقم المدني» أو ما يعادله بوضوح، واستخرج الاسم والصف والشعبة إن ظهرت.
- لا تخلط الرقم المدني مع رقم الطالب أو الهاتف أو التاريخ أو أي أرقام أخرى.
- حوّل الأرقام العربية ٠١٢٣٤٥٦٧٨٩ والفارسية ۰۱۲۳۴۵۶۷۸۹ إلى 0123456789.
- احتفظ بالرقم المدني كنص؛ لا تحوله إلى عدد ولا تحذف الأصفار في البداية.
- لا تفرض أن الرقم المدني يجب أن يكون من 8 أرقام أو أكثر دون مرجع. استخدم القائمة الرسمية والمستند للتحقق، وأحِل الأطوال أو الصيغ غير المتوقعة للمراجعة.
- عند وجود قائمة رسمية، طابق الرقم المدني معها ثم راجع الاسم والصف والشعبة. اختلاف الهوية أو الشعبة يمنع النشر التلقائي حتى يُحسم.
- يمكن تطبيع المسافات والتشكيل للمقارنة فقط، مع الحفاظ على الاسم الرسمي في JSON. لا تستخدم التشابه في الاسم وحده لإسناد شهادة.
- عند غياب قائمة رسمية، استخدم الحقول المقروءة والواضحة في الشهادة. لا تختلق أسماء أو أرقامًا أو صفوفًا.
- إذا كانت الصفحات صورًا، استخدم OCR عربيًا إن توفر، ثم راجع الرقم المدني بصريًا من الصفحة الأصلية. لا تعتمد على درجة ثقة OCR وحدها. إذا تعذرت المراجعة، ضع الحالة قيد المراجعة.
- أي رقم غائب أو ملتبس أو متكرر أو متعارض يُعزل للمراجعة. لا تخمّن الرقم ولا تستبدل ملف طالب آخر.

3. تقسيم PDF وتسميته
- أنشئ PDF مستقلًا لكل شهادة مؤكدة باستخدام الصفحات الأصلية، مع الحفاظ على المقاس والجودة والمحتوى. لا تعِد كتابة الشهادة ولا تحول الصفحات النصية إلى صور.
- سمّ الملف بالرقم المدني: [CIVIL_ID].pdf.
- ضع الشهادات المؤكدة تحت pdfs/[CLASS]/[CIVIL_ID].pdf.
- مثال للمسار: pdfs/5-1/12345678.pdf.
- إذا تكرر الرقم المدني داخل الملف أو تعارض مع شهادة موجودة، لا تستبدل الملف صامتًا. اعزل جميع الشهادات المتعارضة لذلك الرقم حتى المراجعة.
- احفظ الحالات غير المؤكدة منفصلة، مثل review/5-1/page_0007.pdf، أو ملفًا يتضمن نطاق صفحات الحالة.
- لا تضع ملفات review داخل مجلد pdfs المنشور، ولا تربطها في students.json.

4. إنشاء أو تحديث students.json
- إذا كان الملف غير مرفق أو يحتوي []، أنشئ مصفوفة جديدة من السجلات المؤكدة فقط.
- إذا كان موجودًا، تحقق أولًا من أنه JSON صالح وأن الأرقام المدنية غير مكررة. لا تصلح تعارضات الهوية بالتخمين.
- طابق السجلات بالرقم المدني، لا بترتيب الصفحات أو الاسم وحده.
- حدّث حقل pdf للطالب المطابق بعد التحقق من الاسم والصف والشعبة.
- لا تغيّر الأسماء أو الصفوف أو الشعب الموجودة إلا بمصدر رسمي موثوق، وسجل أي تصحيح.
- إذا لم يوجد الطالب في JSON، أضف سجلًا فقط عندما يكون الرقم والاسم والصف والشعبة مؤكدة من المصادر. إذا كانت بياناته ناقصة، ضعه في تقرير المراجعة دون سجل «غير معروف» في قائمة النشر.
- حافظ على سجلات الشعب الأخرى وحقولها وروابطها.
- إذا وُجد طالب في القائمة الرسمية دون شهادة، احتفظ به أو أضفه بالبيانات المؤكدة مع pdf فارغًا ""، ليظهر أن شهادته لم تُرفع بعد.
- لا تمسح رابطًا سابقًا لمجرد عدم ورود الطالب في ملف هذه الجولة. إذا ثبت وجود تعارض في رابط سابق، سجله وامنع إدراج الحالة ضمن حزمة جاهزة للنشر حتى الحسم.
- احفظ الملف UTF-8 كـمصفوفة JSON صحيحة، دون تعليقات أو فواصل زائدة.

صيغة السجل:
{
  "civil_id": "12345678",
  "student_name": "الاسم الرسمي للطالب",
  "grade": "الخامس",
  "class": "5-1",
  "pdf": "pdfs/5-1/12345678.pdf"
}

5. التحقق النهائي
- افتح كل ملف PDF ناتج، وتأكد من عدد صفحاته ومن مطابقة رقمه واسمه لاسم الملف وسجل JSON.
- تأكد من أن كل شهادة منشورة لها سجل مطابق، وأن كل رابط جديد في JSON يشير إلى ملف صحيح موجود في حزمة هذه الجولة.
- تحقق من عدم تكرار الأرقام أو أسماء الملفات، ومن استخدام مسارات نسبية آمنة تبدأ بـ pdfs/ وتنتهي بـ .pdf، دون ../ أو روابط خارجية.
- أحصِ كل صفحات المصدر: شهادات مؤكدة + صفحات معزولة للمراجعة + صفحات غير شهادات موثقة. لا تُسقط صفحة دون تفسير، ولا تكرر إسنادها.
- قارن مع القائمة الرسمية إن توفرت وحدد الطلاب الذين لم تصل شهاداتهم.
- روابط الجولات السابقة لا يمكن إعلان صحتها دون إتاحة ملفاتها. اذكر حدود التحقق بوضوح.
- أنشئ سجل مطابقة لكل شهادة يتضمن: ملف المصدر، رقم الصفحة أو نطاقها، الرقم المدني، الاسم، الشعبة، المسار الناتج، الحالة، وسبب المراجعة إن وجد.

6. التسليم
سلّمني ملفات فعلية قابلة للتنزيل:
أ) ZIP باسم certificates-2026-2027-term1-[CLASS]-publish.zip يتضمن:
   - pdfs/[CLASS]/ والملفات المؤكدة فقط.
   - students.json المحدّث كاملًا.
   هذا ZIP لا يحتوي الحالات غير المؤكدة.
ب) students.json نفسه كملف مستقل.
ج) تقرير مختصر report.txt وسجل مطابقة manifest.csv بترميز UTF-8.
د) ZIP منفصل للحالات قيد المراجعة، إذا وجدت، لا يُرفع للموقع.

اذكر في التقرير:
- عدد صفحات المصدر والشهادات المؤكدة والملفات الناتجة.
- عدد الأرقام المدنية المؤكدة والصفحات غير المقروءة والتعارضات والتكرارات.
- عدد سجلات JSON المضافة والمحدّثة والطلاب الذين لا توجد لهم شهادة.
- أي صفحات مستبعدة وسببها، وأي حدود للتحقق.
- ما هو جاهز للرفع وما يحتاج مراجعة.

لا ترفع الملفات إلى GitHub ضمن هذه المهمة؛ سلّمها للمراجعة أولًا. ابدأ بشعبة واحدة، وعالج جميع صفحاتها مع عزل الاستثناءات. بعد اعتماد التجربة نكرر العملية مع بقية الشعب باستخدام JSON المحدّث.
````

### استخدام المخرجات في المشروع
1. راجع التقرير والحالات المعزولة، وافحص المطابقة بين الشهادة والطالب.
2. انسخ `pdfs/` من الحزمة إلى المستودع، دون حذف شهادات الشعب السابقة.
3. حدّث `students.json` بالملف الكامل الناتج من آخر جولة.
4. لا ترفع حزمة المراجعة أو قائمة الطلاب المصدرية إلى الموقع.
5. قبل اعتماد التحديث، شغّل `python3 scripts/validate.py` للتحقق من JSON والتكرارات والمسارات ووجود ملفات PDF.
6. الفحص البرمجي لا يثبت هوية صاحب الشهادة؛ مراجعة الهوية تتم وفق سجل المطابقة والشهادة الأصلية.
7. بعد نجاح النشر، جرّب البحث والتحميل لعينات من كل شعبة.
